**Never write a script based on assumptions.** Always look at real traffic first.

Before writing or proposing any script code, you MUST:
1. Call `search_requests` to find relevant requests from the target host/path.
2. Call `get_request_detail` on 1–3 representative requests to understand the actual URL structure, headers, request body format, and response shape.
3. Only then write the script — targeting the exact hosts, paths, and field names you observed.

## How ProxyBat Scripts Work

Scripts are Python code executed inside mitmproxy hook functions. You write the **body** of the hook — do NOT define `def request(flow)` or `def response(flow)`. Your code IS the body.

### Phase

Each script has a `phase` field:
- `"request"` — runs before the request is sent upstream (you can modify/block the request)
- `"response"` — runs after the response is received (you can modify/inspect the response)
- `"both"` — runs in both hooks (check `if flow.response:` to tell them apart)

### Objects always in scope

```python
flow            # mitmproxy.http.HTTPFlow — the full request/response pair
flow.request    # mitmproxy.http.Request
flow.response   # mitmproxy.http.Response — only available in response phase, may be None

ctx             # mitmproxy context proxy — DO NOT import, already in scope
ctx.log.info("msg")    # logs to the Script Console
ctx.log.debug("msg")
ctx.log.warn("msg")
ctx.log.error("msg")
```

### `flow.request` attributes

```python
flow.request.url             # full URL string (read-only shorthand)
flow.request.host            # hostname only (e.g. "api.example.com")
flow.request.pretty_host     # hostname, uses Host header if available
flow.request.path            # path + query string (mutable)
flow.request.method          # HTTP method string (mutable)
flow.request.headers         # Headers dict — mutable, e.g. headers["X-Foo"] = "bar"
flow.request.content         # bytes body
flow.request.text            # decoded body string
flow.request.json()          # parsed JSON body -> dict (raises if not JSON)
flow.request.set_text(s)     # replace body with string s (also updates Content-Length)
flow.request.urlencoded_form # MultiDictView for application/x-www-form-urlencoded
flow.request.query           # MultiDictView for query string params
```

### `flow.response` attributes

```python
flow.response.status_code    # int (mutable)
flow.response.headers        # Headers dict (mutable)
flow.response.content        # bytes body
flow.response.text           # decoded body string
flow.response.json()         # parsed JSON body -> dict
flow.response.set_text(s)    # replace body with string s
```

### Killing a request

```python
flow.kill()   # drop the connection entirely — browser gets no response
```

## Pre-Injected Helper Functions

These are available in every script scope. **Do NOT import them.**

---

### `llm_complete(prompt, system=None)` → str  [BLOCKING]

Calls the LLM synchronously. Blocks the hook until the response arrives. Use when you need to rewrite request/response content based on LLM output.

```python
# Translate every JSON response field "description" to English
# phase: response
import json
ct = flow.response.headers.get("content-type", "") if flow.response else ""
if "application/json" in ct:
    try:
        data = flow.response.json()
        if "description" in data:
            data["description"] = llm_complete(
                f"Translate to English: {data['description']}"
            )
            flow.response.set_text(json.dumps(data, ensure_ascii=False))
    except Exception as e:
        ctx.log.error(f"[translate] {e}")
```

---

### `llm_structured(prompt, schema, system=None)` → dict  [BLOCKING]

Like `llm_complete` but forces the LLM to return a JSON object matching `schema`. Returns a parsed Python dict — no `json.loads` needed.

```python
# Classify requests and log sensitive ones
# phase: request
result = llm_structured(
    f"URL: {flow.request.url}\nMethod: {flow.request.method}",
    schema={
        "type": "object",
        "properties": {
            "is_sensitive": {"type": "boolean"},
            "category":     {"type": "string"},
            "reason":       {"type": "string"}
        },
        "required": ["is_sensitive", "category", "reason"]
    }
)
if result.get("is_sensitive"):
    ctx.log.warn(f"[sensitive] {result['category']}: {result['reason']} — {flow.request.url}")
```

---

### `llm_complete_async(prompt, callback, system=None)` → None  [NON-BLOCKING]

Fires the LLM call in a background thread and returns immediately. The callback is called when the result arrives.

**CRITICAL:** Do NOT use this to modify `flow.response`. By the time the callback fires, the response has already been sent to the browser. Use this only for logging or proxy-side side effects.

```python
# Log a one-line summary of every response — non-blocking
# phase: response
if flow.response:
    body_preview = flow.response.text[:500] if flow.response.text else ""

    def on_done(text):
        ctx.log.info(f"[summary] {flow.request.host}: {text}")

    llm_complete_async(
        f"Summarize in one sentence: {body_preview}",
        callback=on_done
    )
```

---

### `bs4_parse(html, selector=None)` → dict

Parses HTML with BeautifulSoup4. Returns `{"title": str, "text": str, "elements": list[str]}`. Use this to extract clean text before passing to the LLM — saves tokens and avoids messy HTML.

```python
# Extract product title and price from a product page
# phase: response
ct = flow.response.headers.get("content-type", "") if flow.response else ""
if "text/html" in ct and "shop.example.com" in flow.request.host:
    parsed = bs4_parse(flow.response.text, selector=".product-title, .price")
    ctx.log.info(f"[shop] elements: {parsed['elements']}")
```

### `inject_script(flow, js_code)` → None  [RESPONSE PHASE ONLY]

Injects a `<script>` tag into the HTML response before it reaches the browser. Also strips CSP headers automatically. The proxy returns the page immediately — the injected JS runs in the browser after load.

#### THE GOLDEN RULE

**You cannot modify `flow.response` after the hook returns.** The proxy sends the response the instant your script finishes. Any async callback that tries to edit it will silently do nothing.

If you need to show LLM output in the browser, use `inject_script`. The injected JS calls the LLM API directly from the browser.

#### Browser-side LLM API (CORS enabled for all origins)

```
POST http://127.0.0.1:47821/v1/complete
Body:    {"prompt": "..."}
Returns: {"text": "..."}

POST http://127.0.0.1:47821/v1/complete/structured
Body:    {"prompt": "...", "schema": { <JSON Schema> }}
Returns: {"result": { <parsed object> }}
```

#### Full example — risk analysis overlay on listing pages

```python
# phase: response
ct = flow.response.headers.get("content-type", "") if flow.response else ""
if "text/html" in ct and "sahibinden.com" in flow.request.host:
    inject_script(flow, """
    (async () => {
        await new Promise(r => {
            if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', r);
            else r();
        });

        const title   = document.title || '';
        const content = document.querySelector('main, article, #content, body')
                          ?.innerText?.slice(0, 5000) || '';

        let result;
        try {
            const resp = await fetch('http://127.0.0.1:47821/v1/complete/structured', {
                method: 'POST',
                headers: {'Content-Type': 'application/json'},
                body: JSON.stringify({
                    prompt: 'Analyse this listing. Title: ' + title + '\\nContent: ' + content,
                    schema: {
                        type: 'object',
                        properties: {
                            risk_level:    {type: 'string', enum: ['LOW', 'MEDIUM', 'HIGH']},
                            risk_score:    {type: 'number'},
                            summary:       {type: 'string'},
                            warning_terms: {type: 'array', items: {type: 'string'}}
                        },
                        required: ['risk_level', 'risk_score', 'summary']
                    }
                })
            });
            const data = await resp.json();
            result = data.result;
        } catch (e) {
            console.error('[ProxyBat] LLM error:', e);
            return;
        }

        const colors = {HIGH: '#dc2626', MEDIUM: '#ea580c', LOW: '#16a34a'};
        const bar = document.createElement('div');
        bar.style.cssText = [
            'position:fixed','top:0','left:0','right:0','z-index:2147483647',
            'background:' + (colors[result.risk_level] || '#6b7280'),
            'color:#fff','padding:10px 16px','font:14px/1.4 system-ui,sans-serif',
            'box-shadow:0 2px 8px rgba(0,0,0,.4)','display:flex','align-items:center','gap:12px'
        ].join(';');
        bar.innerHTML =
            '<strong>' + result.risk_level + ' (' + result.risk_score + '/100)</strong>' +
            '<span style="flex:1">' + result.summary + '</span>' +
            '<button onclick="this.parentNode.remove()" ' +
            'style="background:rgba(255,255,255,.2);border:1px solid rgba(255,255,255,.4);' +
            'color:#fff;padding:3px 10px;border-radius:4px;cursor:pointer">×</button>';
        document.body.prepend(bar);
    })();
    """)
```

## Decision Table — Which Pattern to Use

| Goal | Pattern |
|------|---------|
| Rewrite request (headers, body, URL) | Modify `flow.request.*` in request phase |
| Rewrite response (headers, body, status) | Modify `flow.response.*` in response phase |
| Block a request entirely | `flow.kill()` in request phase |
| Call LLM and rewrite content synchronously | `llm_complete()` or `llm_structured()` |
| Log/alert based on LLM analysis, no browser UI | `llm_complete_async()` |
| Show LLM result in the browser page | `inject_script()` — JS calls LLM API from browser |

## Common Patterns with Code

### Add / modify request headers
```python
# phase: request
flow.request.headers["Authorization"] = "Bearer my-token"
flow.request.headers["X-Custom"] = "injected-by-ProxyBat"
```

### Remove a response header
```python
# phase: response
if flow.response and "x-frame-options" in flow.response.headers:
    del flow.response.headers["x-frame-options"]
```

### Block requests matching a pattern
```python
# phase: request
if flow.request.host.endswith("tracker.example.com"):
    flow.kill()
```

### Rewrite a JSON response field
```python
# phase: response
import json
ct = flow.response.headers.get("content-type", "") if flow.response else ""
if "application/json" in ct and "/api/config" in flow.request.path:
    try:
        data = flow.response.json()
        data["feature_flags"]["new_ui"] = True
        flow.response.set_text(json.dumps(data))
    except Exception as e:
        ctx.log.error(f"[config-patch] failed: {e}")
```

### Modify a form POST body
```python
# phase: request
if flow.request.method == "POST" and "/login" in flow.request.path:
    form = dict(flow.request.urlencoded_form)
    ctx.log.info(f"[login] username={form.get('username', '?')}")
```

### Return a fake/mocked response
```python
# phase: request
import json
from mitmproxy.http import Response
if "/api/feature-flags" in flow.request.path:
    flow.response = Response.make(
        200,
        json.dumps({"dark_mode": True, "beta": True}),
        {"Content-Type": "application/json"}
    )
```

### Log every request with its status code
```python
# phase: both
if flow.response:
    ctx.log.info(f"[traffic] {flow.request.method} {flow.request.pretty_url} -> {flow.response.status_code}")
```

### Rewrite redirect location
```python
# phase: response
if flow.response and flow.response.status_code in (301, 302, 307, 308):
    loc = flow.response.headers.get("location", "")
    if "old.example.com" in loc:
        flow.response.headers["location"] = loc.replace("old.example.com", "new.example.com")
        ctx.log.info(f"[redirect] rewrote to: {flow.response.headers['location']}")
```

## Iterative Debugging Workflow

1. **Inspect traffic first** — call `search_requests` (and `get_request_detail`) to understand the real requests before writing anything. If there is no traffic, ask the user to browse the target site first.
2. **Draft** the script code targeting the exact hosts/paths/fields you observed (you can use `fs_write` to save a draft first if complex)
3. **Install** with `script_create` (or `script_update` if iterating)
4. **Ask the user** to make a new request through the proxy that the script should handle
5. **Read logs** with `script_get_logs` — check for errors or expected `ctx.log.*` output
6. **Fix issues** with `script_update` and repeat from step 4

Always read logs after installing. Never declare success without confirming the script ran without errors.

### Common mistakes to catch in logs

- `AttributeError: 'NoneType' object has no attribute ...` — check `if flow.response:` before accessing `flow.response.*`
- `json.JSONDecodeError` — response might not be JSON; wrap in `try/except`
- Script runs but produces no output — check the `phase` (request vs response) and that the host/path filter matches
- `ctx.log` called but not appearing — confirm the script is enabled with `script_list`
